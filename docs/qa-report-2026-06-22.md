**Fecha**: 2026-06-22
**Build**: dev (`pnpm dev`, `http://localhost:5173`)
**DB**: Supabase sembrado (5 MP + 2 recetas + 7 ingredientes + 2 productos + 1 evento "Master" en_curso + 2 gastos fijos + 1 imprevisto + 2 plan_produccion + 2 evento_productos)
**Alcance**: 13 vistas, ~150 escenarios, 11 dominios (A–K)
**Navegador**: Chrome for Testing 149 headless via Puppeteer
**Modo**: SPA navigation (clicks) + cold-load (deep-link / refresh) tests

---

## 1. Veredicto global

**`PASS-WITH-FIXES`** — el sistema funciona end-to-end en el camino feliz (SPA nav, todos los datos cargados vía Home), las fórmulas financieras son correctas, los flujos pre/durante/post-evento están bien diseñados. Sin embargo, **dos bugs críticos** rompen el camino de deep-link y un bug de UI corrompe números en el reporte. Hay que arreglar antes de declarar el producto "v1 lista".

## 2. Resumen ejecutivo

**Lo que funciona muy bien**:

- El ciclo de vida del evento es completo y la máquina de estados (`planificacion → en_curso → cerrado`) se respeta en todas las vistas. La creación, transición y cierre funcionan sin fricción.
- Las fórmulas financieras son **correctas**: `utilidadBruta = ventas − COGS`, `utilidadNeta = utilidadBruta − gastosOp`, `contribucion = precio − costo`. Las verifiqué manualmente contra los datos reales.
- La navegación SPA funciona impecablemente. AppBar con back, breadcrumb, home icon — todo bien.
- El POS vende correctamente cuando todos los stores están cargados: cart con cantidad, merge al agregar mismo producto, registro con método de pago, toast de éxito.
- El Cierre de Caja se registra con desglose por categoría, total por imprevistos, y el resumen muestra "Cubiertos: N%" como info útil.
- El Reporte con tabs Resumen / Por día / Por producto renderiza los datos correctos una vez que el evento está cerrado.
- Validaciones inline funcionan (duplicate detection de "azúcar" vs "Azúcar" reporta correctamente).
- Responsive (mobile 375px y desktop 1920px) se acomoda sin romperse.

**Lo que está roto**:

1. **Deep-link a `/eventos/:id/productos` o `/pos` muestra datos corruptos**: "(producto sin receta)" en la tabla de pricing, grid del POS vacío o con costo $0. Root cause: las vistas no cargan los stores dependientes en `onMounted` (BUG-001).
2. **El cart puede capturar `costo_unitario: 0`** si el usuario agrega desde `/productos` o si el `epStore` no está cargado. Esta corrupción se propaga a `venta_items`, al cierre, y al reporte, inflando `utilidadBruta` (BUG-002).
3. **El reporte Por producto muestra UUIDs en lugar de nombres** ("417ff4b5-61cd-4dd6-94f2-d3a7222f178f" en vez de "Pan basico"). El cálculo del reporte es correcto, pero la capa de presentación omite el join con el catálogo de productos (BUG-005).

**Otras observaciones relevantes**: input de margen concatena en vez de reemplazar (BUG-004), locale `es-MX` en Intl (BUG-006), agregar-al-carrito desde `/productos` puebla el POS sin contexto (BUG-007).

## 3. Bugs encontrados

### CRÍTICOS (bloquean uso real en producción)

#### BUG-001 — Deep-link / refresh en `/eventos/:id/productos` y `/pos` rompe el join

**Severidad**: CRÍTICA
**Dónde**: `src/views/EventoProductosView.vue` (líneas ~24-67) y `src/views/PosView.vue` (líneas ~143-147)
**Evidencia**: 
- Screenshot: `docs/qa-2026-06-22/screenshots/BUG-001__90-bug-deep-link.png`
- Screenshot: `docs/qa-2026-06-22/screenshots/BUG-001__91-bug-pos-cold.png`

**Repro**:
1. En un browser con la app ya cargada, ir a `/` (home) — todos los stores cargan.
2. En otra pestaña (o refresh), navegar directo a `/eventos/68d65441-c2de-4fe9-8672-67e2267d3b7f/productos`.
3. La tabla muestra todas las filas con `"(producto sin receta)"`, `costo_unitario = $0.00`, `precio_sugerido = $0.00`.
4. Inspeccionar Pinia en DevTools: `recetas.recetas.length = 0`, `productos.productos.length = 0`, `ingredients.materiasPrimas.length = 0` — sólo `events.eventos.length = 1` y `eventoProductos.productosPorEvento.size = 1` están poblados.

**Causa raíz**: La vista sólo carga `epStore.cargarPorEvento(eventoId)` y `useEvents().cargarPorId(eventoId)`. No carga `useProductos().cargarTodas()`, `useRecetas().cargarTodas()`, ni `useIngredients().cargarTodas()`. Como `usePreciosEvento` (en `src/composables/usePreciosEvento.ts:55-100`) hace join por `recetaMap.get(producto.receta_id)`, el lookup retorna `null` y `costo = 0` + `producto_nombre = '(producto sin receta)'`.

**Mismo patrón en PosView**: al hacer cold load de `/pos`, `useProductos().cargarTodas()` se ejecuta pero `epStore.cargarPorEvento(eventoEnCurso.id)` NO. Resultado: grid del POS vacío aunque haya productos configurados para el evento activo.

**Fix sugerido**:
```js
// EventoProductosView.vue onMounted
onMounted(async () => {
  if (eventoId.value) {
    await Promise.all([
      cargarPorId(eventoId.value),
      epStore.cargarPorEvento(eventoId.value),
      useProductos().cargarTodas(),
      useRecetas().cargarTodas(),
      useIngredients().cargarTodas(),
    ])
  }
})

// PosView.vue onMounted — agregar:
const epStore = useEventoProductosStore()
if (eventoEnCurso.value?.id) {
  await epStore.cargarPorEvento(eventoEnCurso.value.id)
}
```

O alternativamente, agregar `cargarTodas` para esos stores en `main.ts` o en el `servicesPlugin` para que estén siempre disponibles.

#### BUG-002 — El cart puede capturar `costo_unitario: 0` si el epStore no está cargado

**Severidad**: CRÍTICA
**Dónde**: `src/stores/ventas.store.ts` función `snapshotLinea` (línea ~116)
**Evidencia**: ver `pass3.log`, sección C y G:
```
[22:01:35] [OBS  ] [C   ] C7: cart content = [{"id":"8bcb64d0...","cant":1,"precio":3,"costo":0}]
[22:01:55] [OBS  ] [G   ] G: cart lines = [{"id":"8bcb64d0...","cant":1,"precio":3,"costo":0,"margen":null,"subtotal":3}, ...]
```

**Repro**:
1. Cold load `/` (home carga todo).
2. Navegar a `/productos`. (epStore NO está cargado para el evento activo).
3. Click "Agregar al carrito" en un producto.
4. En `useVentas.store.ts:124-126`:
```js
const ep = productosDelEvento.value.find((e) => e.producto_id === productoId)
const costo_unitario = ep?.costo_unitario ?? 0
```
Como `productosDelEvento` está vacío (BUG-001), `ep` es `undefined` y `costo_unitario = 0`.
5. La venta se registra con `costo_unitario = 0`.
6. El cierre calcula COGS sin contar este producto → `utilidadBruta` se infla.

**Validación**: el cierre de la prueba G15 muestra `Utilidad bruta: $4,500.33`. Sin el bug, debería ser `$4,500.13` (1 galleta × $0.20 = $0.20 menos). Diferencia chica en este caso pero crece con volumen.

**Fix sugerido**: `snapshotLinea` debe **rechazar** agregar al carrito cuando `ep === undefined` (no se puede vender sin pricing configurado). O PosView debe garantizar que el epStore esté cargado antes de permitir clicks.

#### BUG-004 — Input de margen concatena en vez de reemplazar

**Severidad**: MAYOR (UX roto en flujo común)
**Dónde**: `src/views/EventoDetalleView.vue` líneas 97-107 + template línea ~234-244
**Evidencia**: `pass3.log` sección E3: `E3: margen after save = "4050"` (yo tipeé "50", el input tenía "40", resultado "4050")

**Repro**:
1. Abrir detalle de un evento con margen 40%.
2. Click en el input "Margen (%)".
3. Tipear "50" sin borrar el "40" previo.
4. El valor se vuelve "4050" (concatenación), y al guardar se rompe la fórmula (margen = 40.50).

**Causa**: `margenPorcentajeBorrador = ref<string>('')` con `v-model.number` en un `<v-text-field type="number">`. Vue no dispara `update:model-value` al hacer focus, así que el tipeo se concatena al valor existente.

**Fix sugerido**: usar `v-model` puro (string) o agregar `@focus="$event.target.select()"` o `@click:prepend-inner="limpiar"` con un botón clear. Más limpio: cambiar el ref a `number` y manejar el casting al guardar.

#### BUG-005 — Reporte Por producto muestra UUIDs en vez de nombres

**Severidad**: MAYOR (UX roto — el reporte es la entrega final al feriante)
**Dónde**: 
- `src/utils/cierre.ts` línea 219 (`productoNombre: productoId` por defecto)
- `src/composables/useReporteEvento.ts` líneas 101-105 (no enriquece con el nombre)
**Evidencia**: `pass3.log` sección I:
```
"rows": [["🏆", "417ff4b5-61cd-4dd6-94f2-d3a7222f178f", "3", "USD 4,500.03", ...]]
"pagaronOp": "🏆 Productos que pagaron la operación417ff4b5-..., 8bcb64d0-..."
```

**Repro**:
1. Cerrar un evento con ventas.
2. Abrir `/eventos/:id/reporte`.
3. Click tab "Por producto".
4. La tabla y el banner muestran UUIDs en lugar de nombres.

**Causa**: `calcularDesglosePorProducto` retorna `productoNombre: productoId` (línea 219 de `cierre.ts`), y `useReporteEvento` no hace el join con el catálogo de productos para enriquecer.

**Fix sugerido**: en `useReporteEvento.reportePorProducto`, después de calcular, hacer map enriquecido:
```js
const reportePorProducto = computed<ReportePorProducto[]>(() => {
  const eid = id()
  if (!eid) return []
  const items = itemsDelEvento.value
  const calculo = calcularDesglosePorProducto(items)
  // Join con productosStore para nombres reales
  const productosMap = new Map(productosStore.productos.map((p) => [p.id, p]))
  const recetasMap = new Map(recipesStore.recetas.map((r) => [r.id, r.nombre]))
  return calculo.map((row) => {
    const producto = productosMap.get(row.productoId)
    const recetaNombre = producto ? recetasMap.get(producto.receta_id) : null
    return { ...row, productoNombre: recetaNombre ?? row.productoNombre }
  })
})
```

### MENORES (cosméticos / UX)

#### BUG-006 — Hard-coded locale `es-MX` para formatear USD

**Severidad**: MENOR (cosmético)
**Dónde**: `src/components/business/RegistrarVentaDialog.vue:36` y `src/components/business/CarritoPanel.vue:26`
**Detalle**: `new Intl.NumberFormat('es-MX', { style: 'currency', currency: 'USD' }).format(...)`. La app es para un feriante argentino (brief dice "USD, single-user"), pero usar `es-MX` da formato mexicano (puede dar "$X.XX" en vez de "US$X.XX" o similar). El uso de `es-AR` sería más coherente con el target, aunque USD no tiene locale canónico.
**Fix sugerido**: cambiar a `es-AR` o crear constante `LOCALE_NUMERICO = 'es-AR'` en `src/utils/format.ts`.

#### BUG-007 — "Agregar al carrito" desde `/productos` puebla el POS sin contexto

**Severidad**: MENOR (confuso pero no rompe)
**Dónde**: `src/views/ProductosView.vue` líneas 84-91
**Detalle**: la pantalla de catálogo comercial `/productos` tiene un botón "Agregar al carrito" en cada card. El click llama a `useVentas().agregarAlCarrito(productoId, 1)`, que silenciosamente agrega al cart del POS. El usuario en `/productos` probablemente está curando el catálogo, no vendiendo. La acción no es destructiva pero confunde.
**Fix sugerido**: 
- Opción A: quitar el botón "Agregar" de `/productos` (sólo mostrarlo en `/pos`).
- Opción B: redirigir a `/pos` con un toast "Producto agregado al carrito — ir al POS".

#### BUG-008 — Validación inline en MateriaPrimaForm no es visible en el DOM

**Severidad**: MENOR (verificación incompleta)
**Dónde**: `src/components/business/MateriaPrimaForm.vue`
**Detalle**: al submitir vacío, no encontré `.v-messages__message` con texto de error. La validación de duplicados (REQ-CATALOG-5) sí funciona y muestra mensaje claro ("Ya existe una materia prima con el nombre 'Azúcar'"). Pero las validaciones de campo vacío y de costo negativo no se hicieron evidentes en mi inspección automatizada.
**Hipótesis**: las validaciones pueden ser:
- Mostradas en otro elemento (atributo title, aria-describedby)
- Renderizadas inline pero mi selector no las capturó
- Aplicadas como `required` HTML5 que sí bloquea submit pero sin mensaje visual claro
**Fix sugerido**: revisar manualmente que cada validación tenga mensaje visible en español, o agregar explicit `error-messages` prop a cada `v-text-field`.

## 4. Observaciones (no son bugs, son oportunidades)

- **OBS-001**: Validaciones funcionan para nombre duplicado (mostrado correctamente: "Ya existe una materia prima con el nombre 'Azúcar'"). Las validaciones de campo vacío y costo negativo pueden existir pero requieren inspección manual adicional.
- **OBS-002**: Banner evento activo en home desapareció correctamente después de cerrar el evento (en J section ya estaba cerrado). No es bug, es comportamiento esperado.
- **OBS-003**: useResumen.contadores siempre muestra `cierresCaja = 0` (ver `useResumen.ts:109`: `cierresCaja.value = 0` hardcoded). El contador "Cierres de caja" del home no se actualiza con datos reales. Hallazgo preliminar confirmado.
- **OBS-004**: `EventosView.vue:123` pasa `costo-total={0}` a `EventoListItem`. Hallazgo preliminar confirmado — el costo total nunca se calcula en la lista.
- **OBS-005**: `useProyeccionCostos.ts:137` mapea `productoPrecioPorReceta.get(fila.id)` cuando debería ser `fila.receta_id`. Mi prueba con break-even (E section) SÍ mostró el cálculo correctamente ("Necesitás vender 6 unidades..."), así que el bug no se manifiesta siempre — sólo cuando hay un producto_id que NO es igual al fila.id. En este dataset los IDs coinciden por suerte.
- **OBS-006**: El cart no persiste entre refresh (caveat documentado en REQ-POS-6, ver `ventas.store.ts:30`). Esto es por diseño (offline-sync es un slice futuro). Documentar bien al usuario.
- **OBS-007**: `useProyeccionCostos.ts:144` `precioMinimoSugeridoPorProducto` siempre devuelve 0 cuando `costoPorUnidad = 0` (receta sin ingredientes). Buen guard pero silente.
- **OBS-008**: Las pruebas no exploraron `EventosView.vue:67` que oculta el FAB cuando hay ≥5 eventos y muestra un botón "Nuevo evento" inline. Esto está bien diseñado (UX-24).
- **OBS-009**: El Cart en /pos se cargó con `costo=0` por el BUG-002 pero la UI lo mostró como si todo estuviera OK. El usuario no tiene indicación visual de que el costo sea $0 — esto enmascara el bug.
- **OBS-010**: Cuando el evento pasa a `cerrado` durante el flujo, el `BannerEventoActivo` desaparece (correcto). Pero la card "Post-evento" del Home (`HomeView.vue:144`) muestra `ultimoCerrado.nombre` si hay alguno. No pude verificar esta transición porque el evento que cerré ya estaba en `ultimoCerrado`.
