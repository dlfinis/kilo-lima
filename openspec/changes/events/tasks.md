## Key Learnings

- **Pure logic first, services second, stores third, components fourth, views fifth, router last.** The TDD dependency chain is: types → estado → useProyeccionCostos → events.service → events.store → components → views → routes.
- **PR2's F2 split is mandatory to stay within 400-line review budget.** `PR2a` (services+stores, ~200 lines) and `PR2b` (components+views, ~380 lines) are independent enough that PR2a can be reviewed while PR2b is being implemented.
- **17 spec files before 26 source files.** Strict TDD means every `.ts` source file (service, store, composable, util) gets its `.spec.ts` first. For `.vue` files, only forms/chips/selectors/grids/cards get specs — thin wrappers (`*ListItem`, `useEvents`, `usePlans`) follow catalog precedent of no dedicated spec.
- **Estado freeze enforcement uses ONE function (`estadoEsEditable`) across 3 enforcement layers** (store guards, UI disable, form lock). The 12-unit-test truth table in PR1-T6 is the contract — no hardcoded `estado === 'cerrado'` strings elsewhere.
- **Cost projection is computed, never stored.** `calcularProyeccion` is a pure function tested with 8 edge cases. The reusable `calcularCostoReceta` from catalog is the single source of truth for cost math — events gets updates for free.
- **Cross-store READ is clean; cross-store WRITE is forbidden.** `useProyeccionCostos` reads from 4 stores in a `computed`. `plans.store` reads `useEventsStore().eventoActual.estado` for the freeze guard but never writes to another store's state.
